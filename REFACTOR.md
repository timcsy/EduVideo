# Studio 2 refactor

0.5.0: editing transactions preserve the active playback state, including timeline seeks, structural edits, live sliders, person gestures and caption styling. New red/green tests cover readable ASR segmentation, caption style normalization/outline rendering, the official model catalog and timed/untimed API responses; 68 unit tests pass. Desktop model weights are no longer packaged: the app streams an explicitly chosen official ggml model into its user-data directory, verifies the published SHA-1, and supports cancellation/removal. Browser-only Chrome integration stores an imported model in IndexedDB and completes a real whisper.cpp WebAssembly transcription. API credentials remain ephemeral. Caption recognition applies configurable character/time limits, and preview/export share five richer Canvas styles. End-to-end UI testing confirms playback time advances while caption style, clip volume and person selection change.

Final 0.4 regression count: 63, including a red/green test ensuring long subtitles are not truncated. The final UI flow also exercises real pointer snapping at a clip edge and splitting subtitle text/time at the playhead before undoing it.

0.4.0: source-time captions (manual edits and splits, SRT, speed/trim/reorder projection, burn-in), bundled local whisper.cpp/base ASR, material library, selection-only person affordances, original offline background presets and a vertical playhead with snapping. `studio-v4.test.js` ran red before its new modules existed, then green. 62 unit tests cover subtitle projection/SRT validation/splitting, safe material removal/reuse, 20ms audio landmark extraction and snap distances. Integration verifies actual encoded subtitle pixels, stored presets/names/captions after reload, the real native recognition process and recognition button. ASR results are clamped to decoded WAV duration because a test exposed Whisper padding the final cue to 30 seconds; forced character-length splitting is disabled because it could put Chinese trailing text into a nearly zero-length cue. Users can split at the playhead and a chosen text caret. Synthetic Chinese speech produced a transcription error; no claim of perfect recognition or real-world quality is made. Backgrounds were generated with the imagegen skill, saved under src/assets/backgrounds, and verified visually.

0.3.0: annotation-tools/UI, clip-tools, editor-ui, mask-refinement and project-package modules add editable slide annotations, speed-aware synchronized editing, per-segment person layout, shape/backdrop styling, mask alpha refinement and uncompressed .eduv packages. studio-pro and package-folder tests were executed red before their new modules existed, then green. 56 unit tests pass, including trim extension, duplicate/speed source mapping, independent person settings, circle geometry, mask alpha boundaries, package media deduplication, revisions and invalid paths/symlinks. Integration now checks real arrow gestures + undo/redo, per-clip visibility/shape/speed, and mixed-speed MP4 with a hidden person in the first interval and background-removed circle in the second. Native package tests exercise real save/open IPC and disk I/O with the chooser path stubbed in an isolated app. Quality under real-world lighting, multi-hour recording and sudden power loss remain untested.

0.2.1 UX: removed editing position/size sliders; the preview provides a direct-move frame and bottom-right proportional resize handle. Gestures persist, support undo, and use the same layout as export. Added pure resize tests (red before implementation, then green). Electron integration dispatches real pointer events to move and resize the person, verifies stored values, and undoes resize before exercising export/reload. 49 unit tests pass. Recording devices/source are grouped in the sidebar, recording state has a visible badge, and the timeline has duration-scaled labels with quieter visual styling.

The desktop entry is studio.html. The original index.html and legacy modules remain available for comparison.

TDD evidence: edit-project.test.js and export-plan.test.js were executed before their implementation modules existed (red), then passed after implementation (green). The new model starts without sample clips, preserves source offsets, and applies a single range to synchronized media. Export consumes the same model.

Modules: edit-project.js owns pure edit operations; export-plan.js validates source ranges; project-store.js atomically persists Blobs with the project in IndexedDB; edited-export.js renders edited intervals with original audio; studio.js owns recording and UI.

Validation: npm test; scripts/test-studio.mjs against an isolated Electron process on debugging port 9226, with fake media enabled. Integration covers recording, source Blob sizes, trimming, export generation and persistence across reload. Exported duration and audio stream presence are checked programmatically; audio is not assessed perceptually.

Studio 2 now includes local background removal, a bundled native MP4 encoder, shared preview/export person layout, export cancellation, portable archives containing original media, device selection, recording pause/resume, reorder and redo. Recording recovery snapshots are saved every five seconds; a crash can lose the most recent unsaved interval. Original camera media is never replaced by a processed copy.

The editing model intentionally keeps screen, camera and microphone synchronized. Live camera mirroring is separate from the optional output mirror setting. System audio availability depends on the capture platform; the Electron capture path currently records microphone audio, not system loopback.

Integration testing includes native MP4 decoding with ffprobe and an assertion that exported duration matches the edit plan within 250 ms. Tests use generated camera/audio sources; subjective segmentation quality under different lighting is not covered by these assertions.

Release 0.2.0 acceptance (2026-09-12): packaged file:// application passed recording pause/resume, timeline handle trimming and undo, two-segment background-removed MP4 export (H.264/AAC), persistence after reload, pre-cancelled export rejection, recovery snapshot restoration, and local 53-page PDF import. The recovery check injects a checkpoint; it is not an hour-long recording/crash stress test. Archive round-trip and malformed-input checks are covered by unit tests. Current output is 1280×720; edits remain synchronized across screen, camera and microphone.
